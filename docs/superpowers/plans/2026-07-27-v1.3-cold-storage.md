# RackStack v1.3 — Cold Storage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Cold Storage — the offline-time-gated progression area from spec §4 (`docs/superpowers/specs/2026-07-25-rackstack-expansion-design.md`) — on top of v1.2's server-authoritative architecture: a 16-block passive track, one offline-only job slot (1h/8h/24h), a 7-upgrade Tapes tree, and new goals.

**Architecture:** Every new mechanic is additive to the v1.2 shared/reducer/action-queue pipeline already in production — no new server routes, no new client transport. New action types (`claimBlock`, `claimAllBlocks`, `resetTrack`, `startJob`, `cancelJob`, `claimJob`, `buyTapeUpgrade`) register in the existing `shared/reducer.js` `HANDLERS` table and flow through the existing `POST /api/actions`. New tunables register in the existing `TUNABLES`/`DEFAULT_CONFIG` schema and appear in the existing admin Balancing tab automatically (it's schema-driven). Cold Storage state lives at `state.meta.coldStorage` — a sibling of the existing `upgrades`/`shardUpgrades`/`repeatable` bags under `meta` — so it survives Migrate and Singularity for free (neither handler touches unlisted `meta` keys today; verified by reading both).

**Tech Stack:** Same as v1.2 — Node 20 ESM, Express 4, better-sqlite3, React 18 + Vite 5, vitest + supertest.

## Global Constraints

- `shared/` modules: pure ESM, zero runtime dependencies (matches v1.2).
- Every mutating handler in `shared/reducer.js` follows the existing contract: takes `(s, action, config, now)`, mutates the already-`structuredClone`d `s` in place, returns `{ok:true, ...}` or `err('code')` — reuse `err()` and the existing error strings (`invalid_target`, `not_met`, `max_level`, `insufficient_credits`) rather than inventing new ones; `applyAction` itself never throws.
- **`TOTAL_BLOCKS = 16` is a hardcoded code constant, NOT a config tunable** — it determines the length of the `blocksClaimed` array (a structural/shape concern, like `TIER_DEFS.length`), and admin-editing an array length live would misalign every existing player's saved array. Every other Cold Storage number (durations, reward curves, multipliers) IS a config tunable, same as v1.2's minigame durations.
- Job offline accrual uses the gap's raw `elapsedSec` in `evaluate()`'s offline branch, **not** the production-capped `cappedSec` — the job's own duration (1h/8h/24h) is its own independent cap; bottlenecking it on the separate, often-smaller economy offline cap (`config.offline.baseCapHours`, default 4h) would make an 8h/24h job structurally unclaimable for a low-uptime-level player.
- `computeColdStorageEffects(meta, config)` is a pure function of `meta`+`config`, recomputed fresh on every call (no caching) — matches how `computeEffects`/`computeMults` already work throughout the codebase.
- Commit style: short imperative summaries ending with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- Run tests with `npm test` (vitest) from repo root; `cd client && npm run build` must stay clean throughout.

- [ ] **Step 4: Create `shared/coldStorage.js`**

```js
import { TOTAL_BLOCKS, JOB_TYPES } from './coldStorageData.js';

const JOB_DURATION_CONFIG_KEY = {
  defrag: 'jobDurationDefragMs',
  index: 'jobDurationIndexMs',
  deep: 'jobDurationDeepMs',
};

export function computeColdStorageEffects(meta, config) {
  const up = (meta.coldStorage && meta.coldStorage.upgrades) || {};
  const bq = config.batchQueue;
  return {
    tapeRewardMult: 1 + 0.05 * (up.compression || 0),
    blockDurationMs: Math.max(4 * 3600000, bq.blockDurationMs - 360000 * (up.robotarm || 0)),
    offlineJobRateMult: 1 + 0.10 * (up.priorityspinup || 0),
    headStartBlocks: up.headstart || 0,
    coldFusionMult: 1 + 0.02 * (up.coldfusion || 0),
    heatCapacityBonus: 100 * (up.heatsink || 0),
    offlineCapHoursBonus: 0.5 * (up.deepuptime || 0),
  };
}

export function blockReward(index, trackCycle, config, csEff, totalOutputPerSec) {
  const bq = config.batchQueue;
  const cycleMult = 1 + bq.blockCycleBonusPct * trackCycle;
  let tapes = bq.blockBaseTapes * (index + 1) * cycleMult;
  if (index === TOTAL_BLOCKS - 1) tapes *= bq.jackpotMultiplier;
  tapes = Math.round(tapes * csEff.tapeRewardMult);

  let flops = 0;
  if ((index + 1) % bq.blockFlopsIntervalBlocks === 0) {
    flops = totalOutputPerSec * bq.blockFlopsSeconds;
  }
  return { tapes, flops };
}

export function jobDurationSec(jobType, config) {
  return config.batchQueue[JOB_DURATION_CONFIG_KEY[jobType]] / 1000;
}

export function jobReward(jobType, config) {
  const bq = config.batchQueue;
  if (jobType === 'defrag') return bq.jobBaseTapes;
  if (jobType === 'index') return bq.jobBaseTapes * bq.jobIndexMultiplier;
  return bq.jobBaseTapes * bq.jobDeepMultiplier; // 'deep'
}
```
