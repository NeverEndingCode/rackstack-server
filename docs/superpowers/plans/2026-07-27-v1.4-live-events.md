# RackStack v1.4 — Live Events Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Live Events (spec §5, `docs/superpowers/specs/2026-07-25-rackstack-expansion-design.md`): DB-authored themed events that layer a config-modifier overlay plus a goal ladder on top of the running game, with per-user personal windows, a per-event leaderboard, a seasonal auto-scheduler, and full coordinator authoring from the admin dashboard.

**Architecture:** An event is **a config overlay + a goal ladder** — no special cases in the rules engine. The overlay is applied **at read time only** (`getEffectiveConfig()` merges an active event's `modifiers` over the stored config); the stored config document is never mutated, so an event ending needs no cleanup, an admin editing the Balancing tab mid-event doesn't fight the overlay, and a crashed server can't leave modifiers permanently baked in. Ladder progress is an event-scoped delta against a per-user baseline snapshotted at personal start. Rung claims are **manual actions** (`claimEventRung`), reusing the exact `claimGoal`/`claimRepeatable` pattern already in `shared/reducer.js`, which is what makes the spec's 48h post-event grace period meaningful.

**Tech Stack:** Same as v1.3 — Node 20 ESM, Express 4, better-sqlite3, React 18 + Vite 5, vitest + supertest.

## Global Constraints

- `shared/` modules: pure ESM, **zero runtime dependencies** (matches v1.2/v1.3). Event *definitions* live in the DB, but all event *math* (progress, rung eligibility, overlay merge) lives in `shared/` so client and server compute identically.
- Every mutating handler in `shared/reducer.js` keeps the existing contract: `(s, action, config, now)`, mutates the already-`structuredClone`d `s`, returns `{ok:true, ...}` or `err('code')`; `applyAction` never throws. Reuse existing error strings (`invalid_target`, `not_met`, `max_level`, `insufficient_credits`, `cooldown_active`) — **no new error strings**.
- **Every index/key taken from an action payload must be validated before any property access** — reuse `validIndex(index, length)` for rung indices. This class of bug (`index: '__proto__'`/`'push'`) has been found twice in prior reviews; do not reintroduce it.
- **Event ids and rung indices are user-supplied.** Look them up with `.find(e => e.id === id)` / validated integer indices, never as bare object keys.
- The stored config document is **never** written with event modifiers merged in. `getConfig()` keeps its current meaning (admin-authored baseline); gameplay reads go through `getEffectiveConfig()`.
- Modifier overlays are validated with the existing `validateConfig()` **after merging onto DEFAULT_CONFIG** — an overlay that would produce an out-of-range document is rejected at authoring time, not at activation time.
- Commit style: short imperative summaries ending with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- `npm test` from repo root; `cd client && npm run build` must stay clean throughout.

### Task 1: Shared event model — metrics, overlay merge, ladder math

**Files:**
- Create: `shared/events.js`
- Test: `tests/events.test.js`

**Interfaces:**
- Consumes: `shared/configSchema.js` (`DEFAULT_CONFIG`, `validateConfig`, `getAtPath`, `setAtPath`, `TUNABLES`).
- Produces:
  - `EVENT_METRICS` — the closed set of ladder metric ids with their extractors:
    ```js
    { flopsEarned: (meta) => meta.stats.lifetimeFlopsAllTime,
      minigamesWon: (meta) => meta.stats.minigamesWon,
      blocksClaimed: (meta) => meta.stats.blocksClaimedLifetime,
      tapesEarned:  (meta) => meta.stats.tapesEarnedLifetime,
      wafersEarned: (meta) => meta.stats.totalWafersEarned }
    ```
    (Note: `tapesEarnedLifetime` does **not** exist yet — Task 2 adds it to `meta.stats`, since v1.3 only tracked the tapes *balance*, which decreases on spend and so can't serve as a monotonic ladder metric.)
  - `EVENT_METRIC_IDS` — `Object.keys(EVENT_METRICS)`, for validation.
  - `eventMetricValue(metricId, meta) -> number` — validated lookup; returns `null` for an unknown id (never throws, never bare-key indexes).
  - `mergeEventModifiers(baseConfig, modifiers) -> config` — deep-clones `baseConfig`, applies each `{path, value}` modifier via `setAtPath`, returns the merged doc. Modifiers are a **flat array of `{path, value}`**, not a nested partial object — paths are validated against `TUNABLES` so an overlay can only touch known tunables.
  - `validateModifiers(modifiers) -> {ok:true} | {ok:false, errors:[]}` — every entry has a `path` present in `TUNABLES`, a numeric `value`, and the merged result passes `validateConfig(mergeEventModifiers(DEFAULT_CONFIG, modifiers))`.
  - `validateLadder(ladder) -> {ok:true} | {ok:false, errors:[]}` — 1–20 rungs; each `{metric, target, reward}` where `metric ∈ EVENT_METRIC_IDS`, `target` is a positive finite number, `reward` is `{wafers?, tapes?, flops?}` with non-negative finite numbers and at least one key; targets must be **strictly increasing within a given metric** (a ladder that goes backwards is an authoring error).
  - `rungProgress(rung, meta, baseline) -> {current, target, met}` — `current = max(0, eventMetricValue(rung.metric, meta) - (baseline[rung.metric] ?? 0))`.

**Files:**
- Modify: `server/configService.js`

- Modify: `server/index.js` (boot: seed + scheduler), `server/stateService.js` (use effective config; join-on-login)
- Test: `tests/eventService.test.js`

**Interfaces:**
- `server/configService.js` gains `getEffectiveConfig()` → `{version, data, eventId|null}`: `getConfig()` when no active event; otherwise `mergeEventModifiers(getConfig().data, activeEvent.modifiers)`. Cached per `(configVersion, eventId)` and invalidated on config write **and** on any event activation/deactivation. **`getConfig()` keeps its current meaning** (admin baseline, what the Balancing tab reads/writes).
- `server/eventService.js`:
  - `activateEvent(id, now)` — ends any currently-active event first (enforcing one-active), sets status/window, invalidates the effective-config cache. Returns `{ok}|{ok:false,error}`.
  - `endEvent(id, now)` — status `'ended'`, invalidates cache. Personal windows are **not** truncated here (they tail per §5.3) except by the next activation.
  - `runScheduler(now)` — activates `scheduled` events whose `starts_at <= now`; ends `active` events whose `ends_at <= now`; materializes `recurrence` into next-occurrence windows. Idempotent; safe to call repeatedly.
  - `joinEventIfEligible(userId, state, now)` — called from the state-load path: if an event is active and the user has no `meta.eventProgress` for it, snapshot `baseline` from the five metrics, compute `endsAt = min(now + eventDurationMs, activeEvent.ends_at + 24h)` per §5.3, write `meta.eventProgress` and an `event_participation` row. If `meta.eventProgress` exists for a *different* (now-superseded) event, clear it.
- `server/stateService.js`: `loadEvaluateAndSchedule` uses `getEffectiveConfig().data` for `evaluate`/`applyAction`, and calls `joinEventIfEligible` after evaluate. **`GET /api/state`'s response gains `activeEvent` and `eventProgress`.**
- `server/index.js`: `seedSeasonalEvents()` + `runScheduler(Date.now())` at boot, then `setInterval(() => runScheduler(Date.now()), 3600_000)` (hourly per spec).

### Task 5: Reducer — `claimEventRung` and the opt-out action

**Files:**
- Modify: `shared/reducer.js`
- Test: `tests/reducer.events.test.js`

**Interfaces:**
- `{type:'claimEventRung', index}` → `{ok:true, reward, rungIndex}` | errors:
  - `invalid_target` — no `eventProgress`; `index` fails `validIndex(index, ladder.length)`; already in `rungsClaimed`.
  - `not_met` — `rungProgress(...).met === false`.
  - `cooldown_active` — past the 48h grace period (`now > eventProgress.endsAt + 48h`).
  - On success: credit `reward.wafers`/`reward.tapes`/`reward.flops` (flops → `run.credits` **and** `run.lifetimeRun`, matching how `claimAnomaly` and `blockReward`'s FLOPS bonus already do it; tapes → `coldStorage.tapes` **and** `stats.tapesEarnedLifetime`), push `index` into `rungsClaimed`.
- **The ladder is not in `state`** — it lives in the DB. `applyAction`'s signature is `(state, action, config, now, rng)`, so the ladder must reach the reducer via **`config`**: `getEffectiveConfig()` attaches the active event as `config.__activeEvent = {id, ladder, endsAt}` (a non-tunable, non-validated runtime field — document clearly that `validateConfig` never sees it because it's attached *after* validation, and it must never be persisted). The reducer reads `config.__activeEvent`; if absent, `claimEventRung` returns `invalid_target`.
- `{type:'setLeaderboardOptOut', optOut}` → `{ok:true}` — boolean-validated; mirrored to the `users` column by the route layer (the reducer only records it in `meta` for client display).
